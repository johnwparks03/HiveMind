# HiveMind

Team knowledge-finding tool, Windows-only MVP. A user searches their own files first; if nothing matches well, it searches metadata of files teammates have made public, and the user can download a match from the owner's laptop through a short-lived S3 relay that works across separate networks. This is a demo build: there is one environment (dev), and no production concerns.

## Architecture (hard rules)
- Three parts: **local agent** (`agent/`, Python + FastAPI on `127.0.0.1`), **React frontend** (`frontend/`, React + Vite), **central service** (`infra/` + `central/` or similar, AWS). The exact central code layout is set in E0-S1.
- The frontend talks **only** to the local agent. The agent talks to the central service. The frontend never calls the central service.
- Bedrock (Claude Sonnet 5.5) is called **only** from the central `/llm/*` endpoints. The agent never calls Bedrock or holds AWS credentials.
- The server derives `team_id` from membership. The agent never sends it.
- File bytes touch AWS only as a short-lived S3 transit object (random key = transfer ID, swept after 15 minutes).
- Embeddings are computed locally (sentence-transformers all-MiniLM-L6-v2). File content is never sent centrally for indexing. Only a tag-generation excerpt (default 3,000 characters) passes through the central proxy, and it is never stored or logged.
- Never log request bodies, credentials, tokens, queries or file content.
- One team per user. File types: PDF, DOCX, PPTX, TXT.

## Stack
| Part | Tech |
|---|---|
| Agent | Python, FastAPI, SQLite (file registry + publish queue), Chroma, watchdog, PyMuPDF, python-docx, python-pptx, sentence-transformers, `keyring` (Windows Credential Manager) |
| Frontend | React, Vite (fixed origin, e.g. `http://localhost:5173`), TanStack Query suggested |
| Central | AWS: Cognito, API Gateway (HTTP + WebSocket), Lambda (Python/FastAPI), RDS Postgres (db.t3.micro), S3, EventBridge Scheduler, Bedrock, Secrets Manager/SSM. Infra as code with CDK; boto3. |

## Conventions
- JSON bodies, `snake_case` field names, ISO 8601 timestamps with timezone, UUID IDs (`file_id` is generated by the agent).
- Absent optional values are `null`.
- Errors on every interface use `{"error": {"code": "...", "message": "...", "details": {}}}` with the codes in `API_Contract.md` section 1.
- Interface A (frontend to agent): header `X-HiveMind-Token`, except `GET /auth/token`. Interface B (agent to central): `Authorization: Bearer <Cognito JWT>`.
- Config values (retention 45 days, expiring-soon 7 days, invite lifetime 7 days, excerpt size 3,000, central search cap 20, publish concurrency 5, Bedrock model ID, transfer ack timeout 60 s, sweeper age 15 min) must be configuration, not literals scattered in code.
- Idempotent central operations: retried `PUT /files/{id}` must produce one row; `DELETE` of a missing row returns 204.
- Match the style of surrounding code. Add tests for new behavior.

## AWS (shared demo account)
- There is one shared dev stack. Region, account and model access are set in E0-S2; record them here when known. Do not guess a region or model ID.
- Only one person deploys the shared stack at a time. Coordinate before running a deploy or destroy; do not destroy resources you did not create.
- Never commit AWS credentials, Cognito secrets or DB passwords. Use Secrets Manager/SSM and local environment variables.
- The Bedrock model ID is a config value copied from the Bedrock console.

## Known limitations (do not try to fix)
Startup-token endpoint is protected only by CORS/Origin; no SSO/MFA; no email verification; no Bedrock usage caps; transfers work only while the owner's agent is online; central search is metadata-only; tags come from the first part of a file only; either-date matching; S3 expiry is approximate (~16 minutes); the access log keeps `file_id`s only.
