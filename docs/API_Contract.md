

This contract is derived from the feature list. Paths, field names, header names, and status codes are **my proposals** unless a decision from our discussion dictates them. Section 7 records the decisions made on the first draft and lists what is still open.

## 0. Interfaces

|#|Interface|Caller → Provider|Transport|
|---|---|---|---|
|A|**Agent API**|React frontend → local agent|HTTP on `127.0.0.1`|
|B|**Central API**|Local agent → central service|HTTPS (API Gateway HTTP API)|
|C|**Relay**|Central service ↔ local agent|WebSocket (API Gateway WebSocket API) plus presigned S3 URLs|

The frontend never calls the central service. Bedrock is only called from the central `/llm/*` endpoints.

## 1. Conventions

**Format**

- JSON bodies, UTF-8, `Content-Type: application/json`
- Timestamps: ISO 8601 with timezone, e.g. `2026-10-02T14:30:00Z`
- IDs: `file_id` and `transfer_id` are UUIDs. `file_id` is generated by the agent.
- Field names: `snake_case`
- Absent optional values are `null`

**Auth**

- **Interface A:** every request except `GET /auth/token` carries `X-HiveMind-Token: <startup token>`. The agent binds to `127.0.0.1` only and allows CORS only from the React dev server origin.
- **Interface B:** every request carries `Authorization: Bearer <Cognito JWT>`. The server identifies the caller by the token's `sub`. The agent never sends `team_id`, because the server derives it from membership.
- **Interface C:** token validated by a Lambda authorizer on connect (see section 4).

**Errors** (all interfaces)

```json
{ "error": { "code": "owner_offline", "message": "Human-readable text", "details": {} } }
```

**Common error codes**

|HTTP|`code`|Meaning|
|---|---|---|
|400|`invalid_request`|Malformed or missing fields|
|401|`unauthorized`|Missing or invalid token (A: startup token; B: Cognito JWT)|
|403|`no_team`|Operation requires a team and the caller has none|
|403|`forbidden`|Caller does not own the resource|
|404|`not_found`|Resource missing, expired, or not visible to the caller|
|409|`conflict`|State conflict (details in the endpoint)|
|503|`service_unavailable`|Central service or Bedrock unreachable or returned invalid output. The UI shows "service unavailable."|

## 2. Interface A: Frontend → Local Agent

Base URL: `http://127.0.0.1:{port}` (port is a config value).

### 2.1 Auth and session

**`GET /auth/token`** (no token required) Returns the startup token only if the request's `Origin` header exactly matches the allowed React origin. The token changes on each agent restart.

```json
// 200
{ "token": "b7f3...random" }
// 403 if Origin does not match
```

**`POST /auth/signup`**

```json
// request
{ "email": "a@firm.com", "password": "..." }
// 201
{ "status": "created" }
```

Errors: `400 password_policy` (details contain Cognito's message), `409 user_exists`, `503 service_unavailable`. The pre sign-up trigger auto-confirms the user, so the frontend calls `/auth/login` next.

**`POST /auth/login`**

```json
// request
{ "email": "a@firm.com", "password": "..." }
// 200
{ "signed_in": true, "email": "a@firm.com" }
```

Errors: `401 invalid_credentials`, `503 service_unavailable`. Credentials are never stored or logged. The refresh token goes to Windows Credential Manager. No Cognito tokens are returned to the frontend.

**`POST /auth/logout`** → `204`. Deletes the stored refresh token, closes the WebSocket.

**`GET /session`** (drives the global status indicator and the startup check)

```json
// 200
{
  "agent": "ok",
  "signed_in": true,
  "email": "a@firm.com",
  "team": { "team_id": "…", "name": "Project Alpha" },   // null if none
  "relay": "connected",                                   // connected | connecting | disconnected
  "central_reachable": true
}
```

### 2.2 Team

**`GET /team`** → `200 { "team": { "team_id", "name" } }` or `{ "team": null }`

**`POST /team`** → create. Request `{ "name": "Project Alpha" }`. `201 { "team_id", "name" }`. Errors: `409 already_in_team`.

**`POST /team/invites`** → `201 { "code": "K7Q2-9XPD", "expires_at": "…" }`. Errors: `403 no_team`.

**`POST /team/join`** → request `{ "code": "K7Q2-9XPD" }`. `200 { "team_id", "name" }`. Errors: `404 invalid_code`, `410 invite_expired`, `409 already_in_team`.

**`POST /team/leave`** → `204`. Side effects: the user's public files are removed centrally, and the agent clears the corresponding publish state locally.

### 2.3 Folders

Folder object:

```json
{
  "folder_id": "…",
  "path": "C:\\Users\\me\\Documents\\Notes",
  "scan_state": "scanning",              // scanning | ready
  "counts": { "total": 142, "indexed": 120, "pending": 20, "failed": 2, "public": 37 },
  "shared": false                        // derived: total > 0 and every file is public
}
```

**`GET /folders`** → `200 { "folders": [Folder] }`

**`POST /folders/pick`** → opens the native Windows folder dialog on the laptop. Long-running; the call returns when the user picks or cancels.

```json
// 200
{ "path": "C:\\Users\\me\\Documents\\Notes" }   // or { "path": null } if cancelled
```

**`POST /folders`** → request `{ "path": "…" }`. `201 Folder`. Starts the initial scan. Errors: `404 path_not_found`, `409 already_watched`.

**`DELETE /folders/{folder_id}`** → stops watching, removes the folder's chunks, and queues an unpublish for every file under it that is public. The unpublish entries survive in the publish queue even though the folder is gone.

```json
// 202
{ "queued_unpublish": 37 }
```

**`GET /folders/{folder_id}/share-preview`** → `200 { "file_count": 142 }`. Used for the confirmation text ("Share 142 files with your team?"). Counts files currently under the folder, including subfolders, that are not already public.

**`POST /folders/{folder_id}/share`** → one-time snapshot. Queues a publish for each currently existing private file. Later additions stay private.

```json
// 202
{ "queued": 142 }
```

Errors: `403 no_team`.

**`POST /folders/{folder_id}/unshare`** → makes every file under the folder private. `202 { "queued": 37 }`.

### 2.4 Files

File object:

```json
{
  "file_id": "…",
  "folder_id": "…",
  "path": "C:\\…\\meeting-notes.docx",
  "filename": "meeting-notes.docx",
  "file_created_at": "…",
  "file_modified_at": "…",
  "index_state": "indexed",              // pending | indexed | failed | missing
  "failure_reason": null,                // e.g. "no extractable text"
  "tags": ["meeting", "roadmap"],
  "no_tags": false,
  "visibility": "public",                // private | public (the user's intent)
  "publish_state": "published",          // null | pending | published | failed (sync status of the latest operation)
  "publish_error": null,
  "published_at": "…",
  "expires_at": "…",
  "last_confirmed": "…",
  "expiring_soon": false                 // within 7 days of expires_at (config)
}
```

**`GET /files`** Query params: `folder_id`, `status` (`all` default, `public`, `private`, `failed`, `expiring_soon`), `limit` (default 100), `cursor`.

```json
// 200
{ "files": [File], "next_cursor": null }
```

**`GET /files/{file_id}`** → `200 File`

**`PUT /files/{file_id}/tags`** → request `{ "tags": ["meeting", "roadmap"] }`. `200 File`. If the file is public, queues a metadata re-sync. Changing tags does not extend expiry.

**`POST /files/{file_id}/publish`** → `202 File` (`visibility: public`, `publish_state: pending`). Publishes immediately with no tag preview. If the file already has tags (generated earlier or edited by the user), tag generation is skipped and those tags are sent as they are; otherwise tags are generated first. Errors: `403 no_team`, `409 file_unavailable` (index state `missing`).

**`POST /files/{file_id}/unpublish`** → `202 File`.

**`POST /files/{file_id}/retry`** → re-queues a failed publish. `202 File`.

**`POST /files/{file_id}/confirm`** → re-confirms an expiring file. `202 File`. Central sets `expires_at` to now + 45 days.

**`POST /files/{file_id}/open`** → agent launches the file in its default Windows program. `204`. Errors: `404 file_missing`.

### 2.5 Search

**`POST /search`**

```json
// request
{
  "query": "meeting notes from 3 days ago",
  "include_teammates": false     // optional, default false; true forces a teammate search even when local results are good
}
```

Flow: the agent calls `/llm/query` and runs the local date-filtered vector search. It calls central search if no local result clears the similarity threshold, **or** if `include_teammates` is `true`. The frontend's "also search teammates" control sets that flag.

```json
// 200
{
  "interpreted": {
    "topic": "meeting notes",
    "date_from": "2026-09-29T00:00:00-04:00",
    "date_to": "2026-09-29T23:59:59-04:00"
  },
  "local_results": [
    {
      "file_id": "…", "filename": "…", "path": "…",
      "file_created_at": "…", "file_modified_at": "…",
      "tags": ["…"], "score": 0.71
    }
  ],
  "teammate": {
    "searched": true,                    // false if local results were good enough (and include_teammates was false) or the user has no team
    "skipped_reason": null,              // "local_sufficient" | "no_team" | null
    "results": [
      {
        "file_id": "…", "filename": "…", "tags": ["…"],
        "file_created_at": "…", "file_modified_at": "…",
        "expires_at": "…", "owner_online": true
      }
    ]
  }
}
```

Errors: `503 service_unavailable` (proxy unreachable or invalid model output; no degraded fallback). Owner identity is not returned.

### 2.6 Transfers

Transfer object (agent view):

```json
{
  "transfer_id": "…",
  "file_id": "…",
  "filename": "…",
  "status": "uploading",     // requested | uploading | ready | downloading | downloaded | failed | expired
  "saved_path": null,        // set when downloaded, e.g. "C:\\Users\\me\\Downloads\\notes (1).docx"
  "error_code": null         // owner_offline | upload_timeout | file_unavailable | download_failed
}
```

**`POST /transfers`** → request `{ "file_id": "…" }`. `202 Transfer`. A duplicate request for an in-flight transfer returns the existing one. Errors: `409 owner_offline`, `404 not_found` (file expired, purged, or not on the caller's team), `400 own_file`.

**`GET /transfers/{transfer_id}`** → `200 Transfer`. The agent polls the central service every 1 to 2 seconds and downloads automatically when status is `ready`. The frontend polls this endpoint.

**`GET /transfers`** → `200 { "transfers": [Transfer] }` (this session's transfers, so the UI can resume after a page refresh).

**`POST /transfers/{transfer_id}/open`** → opens the downloaded file. `204`. Errors: `409 not_downloaded`. _(Proposed; you haven't confirmed this action.)_

## 3. Interface B: Local Agent → Central Service

Base URL: API Gateway HTTP API (config). All requests need `Authorization: Bearer <JWT>`. Unless noted, endpoints are audit-logged (section 5).

### 3.1 Teams

|Method & path|Request|Response|Errors|
|---|---|---|---|
|`POST /teams`|`{ "name" }`|`201 { "team_id", "name", "created_at" }`|`409 already_in_team`|
|`GET /teams/me`|none|`200 { "team": { "team_id", "name" } }` or `{ "team": null }`|none|
|`POST /teams/me/invites`|none|`201 { "code", "expires_at" }` (7 days, multi-use)|`403 no_team`|
|`POST /teams/join`|`{ "code" }`|`200 { "team_id", "name" }`|`404 invalid_code`, `410 invite_expired`, `409 already_in_team`|
|`POST /teams/me/leave`|none|`204`|`403 no_team`|

Leave side effects: the user's `public_files` rows are deleted, their `connections` rows are removed, and if they were the last member the team and its invites are deleted.

### 3.2 Public file metadata

**`PUT /files/{file_id}`** (publish and re-sync; idempotent upsert)

```json
// request
{
  "filename": "meeting-notes.docx",
  "tags": ["meeting", "roadmap"],
  "file_created_at": "2026-09-29T09:00:00Z",
  "file_modified_at": "2026-09-29T11:30:00Z"
}
// 200
{
  "file_id": "…",
  "published_at": "…",
  "expires_at": "…",       // published_at + 45 days on first publish
  "last_confirmed": "…"
}
```

Rules:

- `owner_id` comes from the token and `team_id` from membership.
- If the row exists and belongs to another user: `403 forbidden`.
- A retried PUT produces one row.
- On an existing row, `published_at`, `expires_at`, and `last_confirmed` are **preserved**. Only `confirm` extends expiry (decided).
- Errors: `403 no_team`, `400 invalid_request`.

**`DELETE /files/{file_id}`** → `204`. Idempotent: also `204` if the row does not exist. Another user's file returns `403 forbidden`.

**`POST /files/{file_id}/confirm`** → `200 { "expires_at", "last_confirmed" }`. Sets `expires_at` to now + 45 days. Errors: `404 not_found` (row was purged; the agent marks the file as no longer published).

**`GET /files/mine?limit=&cursor=`** (reconciliation)

```json
// 200
{
  "files": [
    { "file_id": "…", "filename": "…", "published_at": "…", "expires_at": "…", "last_confirmed": "…" }
  ],
  "next_cursor": null
}
```

The agent compares this with its registry and corrects any file the server no longer has.

### 3.3 Central search

**`POST /search`**

```json
// request (already resolved by /llm/query; no second model call)
{
  "topic": "meeting notes",                       // nullable
  "date_from": "2026-09-29T00:00:00-04:00",       // nullable
  "date_to": "2026-09-29T23:59:59-04:00"          // nullable
}
// 200
{
  "results": [
    {
      "file_id": "…", "filename": "…", "tags": ["…"],
      "file_created_at": "…", "file_modified_at": "…",
      "expires_at": "…", "owner_online": true
    }
  ]
}
```

Rules:

- Scope: the caller's team only, excluding the caller's own files and rows past `expires_at`.
- A file matches the date range if its created **or** modified date is inside it.
- Topic matching is Postgres full-text search over filename plus tags.
- Topic `null`: all files in the range, newest first.
- Dates `null`: topic-only search over all non-expired team files.
- Ordering: relevance, then recency. Capped at a configurable maximum (e.g. 20).
- Errors: `403 no_team`.

### 3.4 LLM proxy (Bedrock)

**`POST /llm/query`**

```json
// request
{
  "query": "meeting notes from 3 days ago",
  "local_date": "2026-10-02",
  "timezone": "America/New_York"
}
// 200
{
  "topic": "meeting notes",                       // nullable
  "date_from": "2026-09-29T00:00:00-04:00",       // nullable
  "date_to": "2026-09-29T23:59:59-04:00"          // nullable
}
```

Validation: dates parse and `date_from` is not after `date_to`. Invalid model output returns `503 service_unavailable`. Requires login but not a team. Nothing is stored or logged.

**`POST /llm/tags`**

```json
// request
{ "filename": "meeting-notes.docx", "excerpt": "…first ~3,000 characters…" }
// 200
{ "tags": ["meeting", "roadmap", "q4", "planning", "budget"] }     // 5 to 8 lowercase keywords
```

The excerpt is truncated server-side to the configured maximum. Output is validated for count, length, and plain strings. Invalid output returns `503 service_unavailable`. The agent retries a few times, then publishes with empty tags.

### 3.5 Transfers

**`POST /transfers`** (requester)

```json
// request
{ "file_id": "…" }
// 202
{ "transfer_id": "…", "status": "requested" }
```

Server checks: file exists, not expired, same team as the caller, caller is not the owner, owner has a live connection. Reuses an in-flight transfer for the same file and requester. Creates the transfer record and presigned PUT URL, then sends `upload_request` to the owner's connection (section 4). Errors: `404 not_found`, `400 own_file`, `403 no_team`, `409 owner_offline`.

**`GET /transfers/{transfer_id}`** (requester only)

```json
// 200
{
  "transfer_id": "…",
  "file_id": "…",
  "status": "ready",                              // requested | uploading | ready | failed | expired
  "download_url": "https://…presigned GET…",      // only when status = ready
  "download_url_expires_at": "…",
  "error_code": null                              // owner_unresponsive | file_unavailable | upload_failed
}
```

The presigned GET URL is issued at the moment the requester polls and sees `ready`. If the owner never acknowledges within 60 seconds, status becomes `failed` with `owner_unresponsive`. Other users get `404 not_found`.

**`POST /transfers/{transfer_id}/ack`** (owner) → `204`. Moves status to `uploading`.

**`POST /transfers/{transfer_id}/complete`** (owner) → request `{ "size_bytes": 482113 }` (optional). `204`. Moves status to `ready`.

**`POST /transfers/{transfer_id}/fail`** (owner) → request `{ "reason": "file_not_found" | "not_public" | "upload_error" }`. `204`. Moves status to `failed`.

**S3 presigned URLs**

- Upload: the owner's agent streams the file with `PUT` to the `upload_url`. No auth header.
- Download: the requester's agent issues `GET` on `download_url`. No auth header.
- Object key is the transfer ID. The sweeper deletes the object after 15 minutes.

## 4. Interface C: Relay (WebSocket)

**Endpoint:** API Gateway WebSocket API (`wss://…`).

**Connect**

- The agent connects after login and reconnects automatically on drop.
- A Lambda authorizer validates the Cognito JWT on `$connect`. The mechanism for passing the token (query string or `Authorization` header) must be verified; the agent is not a browser, so a header may work.
- On connect the server stores `connection_id`, `user_id`, `connected_at`. On disconnect it removes the row.
- A user with no team can still connect.

**Messages**

Route selection uses an `action` field.

_Agent → server_

```json
{ "action": "ping" }
```

Sent periodically to keep the connection open. Interval is set after verifying the API Gateway idle timeout.

_Server → agent_

```json
{ "action": "pong" }
```

```json
{
  "action": "upload_request",
  "transfer_id": "…",
  "file_id": "…",
  "upload_url": "https://…presigned PUT…",
  "upload_url_expires_at": "…",
  "ack_deadline_seconds": 60
}
```

**Owner handling of `upload_request`**

1. Check the file is still public and still on disk.
2. If not: `POST /transfers/{id}/fail` with `file_not_found` or `not_public`, and stop.
3. Otherwise: `POST /transfers/{id}/ack`.
4. Stream the file to `upload_url` with `PUT` (no loading the whole file into memory).
5. On success: `POST /transfers/{id}/complete`. On failure: `POST /transfers/{id}/fail` with `upload_error`.

Acknowledgment, completion, and failure go over HTTP, not the WebSocket, so they do not depend on the connection staying open.

## 5. Server-side behavior that affects the contract

**Access log events** (append-only; identifiers, counts, and matched `file_id`s only; never filenames, content, or excerpts)

|Endpoint|`event_type`|`details`|
|---|---|---|
|`POST /search`|`search`|`topic`, `date_from`, `date_to`, `count`, `matched_file_ids`|
|`PUT /files/{id}` (first publish)|`publish`|`file_id`|
|`DELETE /files/{id}`|`unpublish`|`file_id`|
|`POST /files/{id}/confirm`|`confirm`|`file_id`|
|`POST /transfers` and its outcome|`transfer_request`|`file_id`, `transfer_id`, outcome|
|`POST /teams`|`team_create`|`team_id`|
|`POST /teams/join`|`team_join`|`team_id`|
|`POST /teams/me/leave`|`team_leave`|`team_id`|

`/llm/*` calls are not logged with content. Whether to log that a call happened (without content) is not decided.

**Scheduled jobs (not part of any API)**

- Transfer sweeper, every minute: deletes S3 objects older than 15 minutes, marks stale transfers `expired`, and marks transfers with no acknowledgment after 60 seconds `failed`.
- Nightly purge: deletes expired `public_files` rows, expired invites, and stale `connections` rows.

## 6. Agent internal behaviors that the contract assumes

- **Publish pipeline per file:** `POST /llm/tags` (skipped if the file already has tags), then `PUT /files/{id}`. Both steps live in the persistent queue and are retried with exponential backoff, throttled to 5 concurrent requests.
- **Unpublish and re-sync** use the same queue. Only the latest intent per file is kept.
- **Reconciliation:** the agent periodically calls `GET /files/mine` and corrects files the server no longer has.
- **Transfer polling:** the agent polls `GET /transfers/{id}` on the central service every 1 to 2 seconds, then downloads and writes to the Windows Downloads folder with a numeric suffix on collisions.
- **Local search uses `/llm/query`** on every search. If it fails, search returns `503`.

## 7. Decisions

### Settled on review of draft v1

1. **Re-sync does not reset `expires_at`.** Only `POST /files/{id}/confirm` extends it, so editing tags can't silently extend sharing.
2. **Removing a folder unpublishes its public files** (`DELETE /folders/{id}` returns `202 { "queued_unpublish": n }`).
3. **Existing tags skip generation.** If a file already has tags when it is published, the tag call is skipped.
4. **"Search teammates too" is available** through the optional `include_teammates` flag on `POST /search`. I read your "Sure" as wanting this added; tell me if you meant something different.

### Still open

1. **Date range format.** I used ISO date-times with the user's UTC offset and an inclusive end. Plain dates are the alternative. I haven't tested how reliably the model returns either.
2. **Opening a downloaded file** (`POST /transfers/{id}/open`) is my addition and not confirmed.
3. **Header name, port, and token type.** I used `X-HiveMind-Token`. I don't know which Cognito token (access or ID) your JWT authorizer will accept, and the port is undecided.
4. **Pagination.** Cursors on `GET /files` and `GET /files/mine` could be dropped for demo-size data.
5. **WebSocket token passing** needs verifying against API Gateway's authorizer options.
6. **Team-removal notification.** Nothing is pushed over the WebSocket when a user leaves a team. The agent learns through its own `POST /team/leave` call, or through reconciliation if the change happens another way.
7. **Presigned PUT headers.** Whether the signed URL requires a specific `Content-Type` or `Content-Length` depends on how the server generates it. Check this during the relay prototype.
8. **Tag edits on private files.** Setting tags before publishing now means those tags are used as-is (see settled item 3). I haven't checked whether you want the UI to make that clear.

If you'd like this as an OpenAPI (YAML) spec so the frontend and agent can generate types and mocks, I can convert it once the open items are settled.
